# FlClash Pilot：电脑与安卓自动选线

这是一个可实际运行的辅助工具。电脑端已补充对当前选择为嵌套策略组的支持。它帮助你在已有节点中选择响应较快、较稳定的线路；不能保证每个应用、每个时刻的下载带宽最大。

## 文件

- `dist/FlClashPilot.exe`：Windows 本机工具，双击打开，无需安装 Python、Node 或管理员权限。使用 Windows 自带的 .NET Framework 4.x。
- `Android/自动选线.js`：在安卓 FlClash 内运行的配置脚本，**不是独立 APK**；也可以在电脑 FlClash 中使用。
- `source/`：电脑端完整源码及程序清单。
- `验证说明.md`：已验证的行为与尚需实机验证的部分。

本工具没有云服务、账号、遥测或订阅导入功能。它不会要求你把订阅链接、二维码、节点密码或控制口令发到聊天里。

## 电脑：连接后再启用自动选线

1. 保持电脑 FlClash 运行；本工具不会替你改变出站模式。
2. 本版针对 FlClash **v0.9.1** 设计。电脑进入 **工具 → 常规 → 入站 → 外部控制器**。如果实际汉化标签有差别，可发不含口令和订阅信息的常规页面截图。
3. 在 FlClash 内由你启用仅本机的控制接口，地址通常是 `127.0.0.1:9090`。设置一个单独的控制口令；这不是订阅密码。不要绑定 `0.0.0.0` 或开放到公网。不需要打开“允许局域网”。如果你的版本不支持设置口令或没有此功能，先停在这里，使用下方内核脚本或核对版本。
4. 打开 `dist/FlClashPilot.exe`。填入对应本机地址与控制口令，点击“连接 / 刷新策略组”。口令仅保存在运行内存中，关闭后不保存。
5. 选择实际承载流量的“手动选择 / Selector”策略组。如果当前选中另一个策略组，工具会先把这个现有选择作为基准检测，保留恢复原选择的能力；无需先手动拆开嵌套组。若当前选择是直连或拒绝，工具会停止启动，避免替你改变这类选择。本工具只会切到所托管组原有的直接节点，不扩展其他嵌套组的成员，不选择 DIRECT。原组本身如果包含多个地区的节点，自动选择可能改变出口地区；对登录地区敏感的服务应使用其专用组。
6. 先点“只检测一次”，确认结果合理。这个按钮不切换节点。
7. 点击“开始自动选线”后才接管该组。默认每轮完成后等待 60 秒，再检测下一轮；每轮最多 12 个节点、并发 3 个，候选较多时逐轮覆盖。每个请求只访问小型 HTTPS 检测页面，**会产生少量代理流量**。节点很多时可以调大间隔。

工具按最近五次样本的中位延迟、波动及失败比例评分。候选至少有两次成功，连续两轮领先，且改善达到 50 ms 或 20% 的较大者，才会正常切换；正常切换后冷却 3 分钟。当前线路连续两次检测失败时，可跳过冷却，切到本轮检测成功且有足够历史样本的线路。全部失败时保持原选择，不改成直连。

“实际下载 / 上传”显示当前使用量，不是带宽上限。空闲时显示零不会触发换线。本版不通过轮流切换节点、大量下载来测最高带宽，也不根据这个流量读数做带宽排名。

### 暂停、恢复与边界

- “暂停自动”保留最后的节点，不再自动换线。“恢复接管前选择”在配置和选择未被其他操作更改时恢复原选择，包括原来选中的嵌套策略组。
- 你在 FlClash 手动换线，或工具检测到模式、组成员、节点类型变化时，会暂停自动操作。恢复点与本次窗口会话绑定；刷新连接会清除恢复点。
- 工具只能观察 API 提供的模式、节点类型、成员和所托管组的当前选择；**同名节点的服务器或凭证发生变化，不一定能识别为换了配置；嵌套组内部的选择变化也不一定能区分是自动策略还是手动操作**。更新订阅、切换配置或修改节点时，请先暂停工具，再重新连接。
- 工具不关闭已有连接。换线主要影响新建连接，正在进行的下载、视频或通话可能继续使用原连接。API 没有跨客户端的原子锁，其他程序同一瞬间改选仍存在竞争；切换后会重新校验，发现冲突即停止。
- 关闭窗口停止自动选线，保留最后节点；不会开机自启。正在发出的请求无法保证撤回，暂停后请以 FlClash 当前选择为准。
- 全局模式只能托管 GLOBAL 组；规则模式需选择被相应规则实际引用的组。选择一个未被规则使用的组，不会改变应用流量。
- 不要同时在同一个组上运行电脑工具和内核自动策略。程序只允许打开一个本机实例。

## 安卓：在 FlClash 内运行自动选线

手机优先使用 FlClash 自己的 mihomo 内核定时检测，不需要电脑一直开机，不需要把手机控制接口开放给电脑，也不需要安装 Termux 或另一常驻应用。

1. 本版针对安卓 FlClash **v0.9.1** 设计。先备份当前配置及已有覆写脚本。备份保留在你自己设备上，不要上传到聊天。
2. 进入 **工具 → 高级配置 → 脚本 → 添加 → 从文件导入**，选择 `Android/自动选线.js`；也可以新建脚本后粘贴完整内容，保存为“Pilot 自动选线”。**不要把此 JS 当成订阅 YAML 导入，也不要覆盖已有脚本。** 已有脚本需要在本机合并。
3. 回到 **配置**，打开当前配置的菜单，选择 **扩展 → 脚本**，再选择“Pilot 自动选线”，退出扩展页以应用。如原来已有脚本，或“标准”扩展中已有自定义规则 / 代理组，先保留原设置并在本机合并，不能直接用新脚本替换。脚本处理成功时会增加 `[Pilot] 自动 · 原组名` 的自动组，并把它添加为对应手动组中的选项。
4. 回到代理页，先核对当前选项。对于只有代理集合、没有显式节点列表的手动组，新增选项可能影响首次默认项的顺序；以客户端保存的实际选择为准。
5. 在原来的手动组中选择新增的 `[Pilot] 自动 · 原组名`。如果原来选择的是一个限定地区的组，请从那个地区组内部启用，不要跨地区混选。仅包含嵌套组的父组不会被自动展开。
6. 使用你平常觉得慢的应用，观察一至两个检测周期。保持相同网络、相同内容，比较打开速度、卡顿与断线；需要比较 Wi-Fi 和流量时分开记录。手机后台行为仍取决于 FlClash 和系统，是否限制后台由你在手机上决定。

手机端每 300 秒检查一次；只有选中使用该组时才周期检测，响应差距不足 80 ms 时尽量保持当前节点。等待检测的时间、超时与具体切换时机由 mihomo 内核决定。**手机脚本没有实现电脑端额外的连续领先判断和 3 分钟冷却**，不要把两者策略理解为完全相同。

脚本不修改原节点、订阅地址、路由规则、DNS 或控制器。若组引用代理集合且集合尚未启用健康检查，会在运行配置中启用该集合的小型连通性检查；已经启用的集合检查保持原设置。空自动组的兜底是 REJECT，避免静默改成直连。

如果只希望给一个组加选项，可在脚本开头把 `targetGroups: []` 改成你实际的组名，例如 `targetGroups: ["PROXY"]`。节点名和组名可以留在本机，不必发出。

### 手机撤回

先在原手动组中选择原来的节点，再禁用 / 移除这份新增脚本并重新加载原配置。不要删除原订阅或原节点。若本来已有脚本，恢复你自己的脚本备份。

## 如何判断有没有改善

1. 同一网络、同一应用、同一内容，先记录原节点的等待时间 / 卡顿情况。
2. 开始自动选线，等待获得足够样本，再打开新的同类连接。
3. 如果延迟不错但高清视频 / 大文件仍慢，需要进一步比较实际吞吐、套餐限速和线路拥塞；本工具的延迟结果不能证明带宽最大。
4. DNS 只在观察到解析失败或明显的解析等待后，再针对实际配置调整。本工具不套用通用 DNS 模板。

Windows v1.1 已完成本地逻辑及模拟接口验证，实机自动托管和恢复仍需验证；安卓脚本仍需在实际手机加载验证。
